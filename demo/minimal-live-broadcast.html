与「只调 TRTC enterRoom」不同：这里走 TUIRoomEngine 的 startLive， 会在直播业务侧创建直播间，便于你在 直播管理系统 等后台看到房间与监控。strRoomId 即各端统一的直播间 ID（liveId）。 画面通过 Canvas 采集；底层使用 RoomEngine 返回的 TRTCCloud 发布自定义视频轨（_startPublishVideoTrack）。 音频可选：Web Audio 合成音、本地文件（captureStream）或麦克风；通过 TRTC 内部实例发布 audioTrack（演示用）。

观众端报错如何排查（PK / review / WebRTC）

live_engine_pk / 100411：表示当前房间没有进行中的 PK，服务端返回「battle 不存在或已过期」在无 PK 场景下是预期现象。 若仅刷屏日志：可在业务端忽略该错误，或将 TUILiveKit / RoomEngine 升级到最新；与是否「创建房间多传参」无必然关系。

Cannot read properties of null (reading 'review')：多为观众端业务或 UI 组件假设了某字段（如审核、扩展信息）一定存在。 请对直播元数据使用可选链（liveInfo?.xxx），并与正式主播端创建的字段结构对齐。

WebRTC reading 'type'：多为网络抖动、UserSig 过期、或移动端浏览器策略；请确认 HTTPS、票据未过期、主播仍在推流。

seat / 100211：未开启麦位时 SDK 仍可能同步麦位；本页固定 isSeatEnabled: true。

startLive：template_id 与 maxSeatCount 不可同时传：服务端要求 seatLayoutTemplateId（200–999）与 maxSeatCount 二选一。 本页只传模板 ID（单机位 200/600，多人 201/601），不再传 maxSeatCount。

本地预览：推荐使用 npx --yes serve -l 3333 或 python3 -m http.server 3333， 打开 http://127.0.0.1:3333/demo/minimal-live-broadcast.html。 ES 模块从 jsDelivr 拉取 @tencentcloud/tuiroom-engine-js（需可访问外网 CDN）。 Canvas 测试图可在开播前或直播中切换，用于对比接收端清晰度；若 Web 观众端偏糊，可同时检查观众端是否用小窗拉流、码率档位与 TRTC 大小流策略。
